Failure case. At ρ = 0.01 the heap build (0.26 ms, about 77% of the heap’s total time) is barely repaid by about 34
increments. The speed-up falls from 14× to 1.16× with a CI that includes 1, so there is no reliable gain. On the
cloud VM the same case was 0.87× (heap slower), so the sign of the effect at tiny budgets depends on the machine.
By ρ = 0.03 the heap is clearly faster again. A practical implementation could choose the method from the expected
B/N . Model validity, not code correctness. When bits are planned on ĝ, the true energy exceeds Emax in almost
every case, by +8.9% on average with 20 pilots and +65% with 4 (Table 2, Fig. 4b). Noise inflates |ĥ|2 on average,
and the greedy rule preferentially loads the tones whose g was over-estimated. Both methods are affected identically,
because the change cannot fix bad inputs. Limitations. The data are synthetic, the gap model is approximate,
tones are independent, timing comes from a single laptop (background load adds noise), and only the greedy core is
reproduced. The heap’s advantage depends on Python and NumPy implementation details, not only on asymptotics.
